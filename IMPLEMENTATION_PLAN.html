Policy Verification System

Hallucination and Citation Verifier for Policy Question Answering

Implementation Plan · Simple Language for Beginners

📋 What You're Building

An AI system that answers questions about university policies and shows you the proof. Every answer points to the exact policy text it came from. If it can't find proof, it says nothing rather than making something up.

Timeline: 8-12 weeks, working alone, ~10 hours per week.

Big Decisions (Already Made)

These are locked in. Don't change them.

What Decision
Policy documents Download from 3-4 universities (about 20-25 documents total)
How to store them Save a list of where they came from (not the files themselves)
Python version Use Python 3.11 or 3.12 — your 3.14 will cause problems
AI model Qwen3 4B first (faster while learning), upgrade to 8B later
Search database Chroma (simple, works offline)
Fact checker NLI model (says if evidence supports the claim)

The Two Decisions You Make First

Before writing any code, decide these two things. Everything else depends on them.

1. Citation ID Format

How you'll identify which part of which policy said something.

Example: uni_a/academic_integrity/4.2

This means: "University A, Academic Integrity policy, section 4.2"

2. Data Shapes (in schema.py)

Name What it contains
Document University, policy name, title, source, sections
Chunk ID, text, citation ID, university, policy type, section
Claim The statement, citation IDs it came from
ClaimVerdict Claim, is it supported/refuted/unclear, score, evidence chunks
Answer Question, kept claims, removed claims, did we refuse, why
Use Pydantic. It catches bugs where your AI returns garbage shaped data.

10 Phases (Week by Week)

PHASE 0

Setup & Spikes (Week 1)

"Spike" = quick test before building on it

Do three tests:

  • Corpus test: Download one policy from 5 different universities. Keep the 3-4 that extract cleanly.
  • VRAM test: Run Qwen3 4B with embedder + fact-checker on CPU. Check you have enough memory.
  • NLI test: Write 20 fake claim/passage pairs. Test 2-3 fact-checker models.
Done when: `import policyverify` works · schema exists · manifest lists your universities
PHASE 1

Ingestion (Week 2)

Get policies from the internet into a consistent format.

fetch.py → extract.py → normalize.py

Done when: All 20-25 documents are valid · You've read 3 by hand to confirm
PHASE 2

Chunking & Index (Week 3)

Build the searchable database.

Write a manifest recording which embedding model built the index. If you rebuild with a different model and forget, search silently returns nonsense.
Done when: Index builds in one command · Manual search returns relevant chunks
PHASE 3

Retrieval & Generation (Week 4)

Make the AI produce answers.

Use Ollama's JSON mode so the AI outputs valid JSON. Never generate prose and parse it back.
Done when: `scripts/ask.py "question"` returns claims with citations
PHASE 4

The Verifier (Weeks 5-6) — The Core

This is the important part. Spend your time here.

  • nli.py: Does passage support claim? Output: supported / refuted / unclear + score
  • numeric.py: Do numbers match? ("75%" ≠ "80%")
  • citation.py: Does cited section exist? Does passage support claim?
Done when: Every claim has a verdict, score, and evidence IDs
PHASE 5

Abstention & Correction (Week 7)

Teach it to refuse. Move unsupported claims into `claims_removed` instead of deleting them.

Done when: System refuses unanswerable questions and explains why
PHASE 6

Adversarial Dataset (Week 8)

60-80 trick questions across five categories:

  • Cross-university confusion (your signature trap)
  • Numeric traps ("75%" vs "80%")
  • Unanswerable but plausible (test abstention)
  • Negation/exceptions ("except when...")
  • False premise questions
Split into tuning set and held-out test set. Never tune and test on the same questions.
PHASE 7

Streamlit UI (Week 9)

Question box · university filter · color-coded claims · evidence · abstention banner · removed-claims panel

Done when: UI and CLI give identical verdicts (proof they share one core)
PHASE 8

Evaluation (Week 10)

Measure how well it works with five metrics:

Metric What it means
Claim P/R Are "supported" claims really supported?
Citation accuracy Cited section exists AND supports claim
Hallucination rate % of claims not backed by evidence
Abstention quality How many unanswerable questions did you refuse?
Latency How long it takes (retrieve / generate / verify)
Done when: One command produces the metrics table
PHASE 9

Hardening & Deliverables (Weeks 11-12)

Polish and finish:

  • Add hybrid retrieval (BM25 + dense, ~10 lines)
  • Error analysis (pick 15 failures, categorize them)
  • README (people read this, not your code)
  • Architecture diagram
  • 5-minute demo script

Things to Watch Out For

Problem How to fix it
PDF extraction is garbage Pick universities by extraction quality in week 1; prefer HTML
Qwen returns invalid JSON JSON mode + Pydantic + one retry + fail loudly
NLI model weak on policy text Test in week 1, not week 6. Fallback: add LLM judge tier
Run out of VRAM Start with 4B; confirm embedder and NLI are on CPU
Chunks wrong size Make it a config value; inspect real chunks early

Quick Reference

Hardest parts:

  • The verifier (spend time thinking here)
  • Citation scheme (decide early)
  • Data shapes (get Pydantic right first)

Easiest wins:

  • Numeric guard (catches real errors, ~30 lines)
  • Citation existence check (deterministic)
  • Progress tracker (make threshold a config value)

Most common failures:

  • Model/index mismatch (write the index manifest!)
  • Parsing prose claims (use JSON contract)
  • Tuning and testing on same questions (split your dataset!)
